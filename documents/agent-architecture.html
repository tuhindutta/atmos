Atmos · Architecture

Agent

The web app creates a LangGraph agent at startup. For each chat request, it supplies the selected thread's text history, streams agent events, and saves the completed turn with its execution trace.

Master-agent request path

FastAPI lifecycle Checks configuration and initializes memory, shell manager, and model.
Build tools Combines shell, resource, memory, sub-agent, and progress tools.
LangGraph agent create_agent runs a model/tool loop with the master prompt.
Chat request Loads up to 20 messages for the active thread and supplies the new user message.
Stream + save Events are streamed as SSE; the final response and trace are persisted.

The app serializes chat execution with a request lock. The active thread ID is provided to the memory-history tool through request-local context.

Agent loop and outputs

Model ChatOpenAI, configured by OPENAI_MODEL (default: gpt-6-luna).
  • Receives the system prompt and conversation text.
  • Chooses whether to answer or invoke a tool.
Tool execution Tool results return to the agent loop so the model can continue.
  • Shell, memory, resource, and progress tools.
  • query_sub_agent can run a narrower child agent.
Streamed events stream_agent_events() adapts LangGraph events to the UI.
  • AI deltas are streamed but not saved as trace entries.
  • Tool and other non-delta, non-final events are collected.
  • The final answer is stored with that trace.

Optional child-agent path

Master agent Calls query_sub_agent with a focused query and system prompt.
→
Child agent Uses the shared model with its own prompt and a separate tool set.
→
Result + cleanup Returns its final response to the master and stops its managed terminal.

The child receives persistent-shell tools and Atmos resource tools; it does not inherit the master's memory or progress tools.
