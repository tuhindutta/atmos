Atmos · Architecture

Memory

Short-term conversation history and durable long-term memories share a SQLite database. Conversation messages and agent event traces are stored separately and linked by message ID.

Conversation lifecycle

Chat request POST /api/chat carries a thread ID and user message.
Thread context The request's thread ID is set for the active agent/tool execution.
Load history recent_messages() reads up to 20 messages for that thread.
Run agent Agent events stream to the client; non-delta, non-final events are collected as a trace.
On a final answer
  • save_turn() inserts the user message and assistant answer.
  • Collected event payloads are attached to the assistant message.
  • Failed/incomplete turns are not saved as completed turns.
Read back history and trace
  • recent_messages_with_events_tool reads the active thread when called by the agent.
  • GET /api/threads/{thread_id}/messages serves messages with events to the UI.
  • Stored event payloads are JSON, including tool start/end/error records.
The agent's ordinary prompt history contains message role and text only. It can retrieve prior event traces by calling the history tool; those traces are not automatically appended to every prompt.

SQLite schema

Default database: .atmos/agent_memory.sqlite3

conversation_messages Short-term chat, scoped by thread_id.
  • id — message key
  • role — user or assistant
  • content — message text
  • created_at
conversation_events Agent trace records associated with assistant messages.
  • assistant_message_id — foreign key
  • event_type — event category
  • payload — serialized event JSON
  • Deleted with its message
long_term_memories Durable, shared memories, independent of thread history.
  • content — unique, case-insensitive text
  • created_at / updated_at
  • Read and written with memory tools
